# Tollgate demo site

Static site, no build step, relative URLs only. Every page requests only its own files, with one exception: the workspace's Live chain reads public Ethereum data from `https://ethereum-rpc.publicnode.com` and cross-checks it against `https://eth.drpc.org` (roles swap on fallback), and `app.html`'s Content Security Policy allows exactly those two origins in `connect-src`. Serve the folder over HTTP from any path (for example `python3 -m http.server`); it will not run from `file://`.

- `index.html`: product page. The hero runs the real verifier on the sample chain and shows the time it took.
- `app.html`: the analyst workspace. Sidebar: Live chain (first), Overview (Dashboard, Demo stream), Screening (Screen addresses, Alerts, Counterparties, Monitoring), Sanctions lists (List versions, List archive), Receipts (Receipt explorer, Verify receipts), Evidence (Evidence packs, Proof gap), Network, Admin (Policy and roles, Activity log, Settings), Help (Get started, API examples, How it runs, Limits). Everything except Live chain runs in the browser on synthetic demo data; the sanctions list is the real bundled snapshot. State is kept in localStorage as a short op log (Reset demo erases it). Code is in `js/ws/`; `scripts/verify_pack.mjs` checks an evidence pack offline. Verify receipts holds the original tools: verify the sample chain, Simulate tampering, and the receipt file editor (Edit receipt file; the old `#raw` link opens it).
- Live chain (`js/ws/chain.js`, `js/ws/view-chain.js`): real Ethereum mainnet. The browser polls the public node every 12 seconds (paused while the tab is hidden; exponential backoff from 3 s to 60 s and a switch to the fallback node after two failures, with a status chip that says why). Before anything is signed, the same log range is read from the other node and compared log by log (address, block hash, topics, data): a block the two disagree on is held, and dropped unsigned if they still disagree on the third poll, and if the other node cannot be reached the page waits one poll and then signs from one node, saying so in the source line. One dishonest node can delay or drop records but cannot get a fabricated transfer signed. It follows USDC (`0xA0b8…eB48`) and USDT (`0xdAC1…1ec7`) Transfer logs block by block, screens sender and receiver of every transfer against the bundled OFAC snapshot with the workspace's exact-match function, signs each decision into its own rolling ledger (receipt ids `c1, c2…`, rolled at 300, verifiable with the page's verifier), and draws transfers and USD per block. It also reads the issuers' freeze events (USDC Blacklisted / UnBlacklisted, USDT AddedBlackList / RemovedBlackList) live and for the last 5,000 blocks on load (1,000 on the fallback node), each with whether the address is on the bundled list and the list's date. Hits are never simulated: the KPI reads "0 hits in N transfers" until a real one happens. "Replay a known sanctioned address (historical)" fetches one real transfer from the chain (1 USDC to an address on the list, block 13,180,202) and signs it as `historical_replay`; it is labelled Historical and not counted as a live hit. Limits measured on 2026-11-10: publicnode answers `eth_getLogs` over about 5,000 recent blocks and refuses older blocks without a token; drpc answers ranges of about 100 blocks, old blocks included (it serves the replay); both answer JSON-RPC batches and send CORS headers. Settings has "Connect to Ethereum mainnet automatically" (on by default) for visitors who do not want the requests.
- Time ranges and saved records (`js/ws/timerange.js`, `recordstore.js`, `range-ui.js`): the Dashboard volume chart and tiles and the Live chain History chart take 1D, 1W, 1M, 3M, 6M, 1Y, 3Y (hourly, 6-hourly, daily, weekly, weekly, monthly, monthly buckets, in the zone chosen in Settings; the choice is kept per view in the prefs). Buckets before the first record read "No records" (the demo history is seeded for 30 days only and is never stretched); on the Live chain, buckets in which the page was not recording read "Not recording", distinct from zero transfers. The Live chain saves what it screens in IndexedDB (`tollgate-demo-records`; memory with a visible notice when the browser blocks it): per-minute buckets (compacted into hours after 7 days), every hit with its signed receipt and every issuer freeze event kept indefinitely, and the latest 20,000 full transfer records. Each record has `block_time` (the chain's one-second timestamp) and `screened_at` (this page's clock, milliseconds, signed into the receipt). Saved records card: Export CSV, Clear. Recording runs only while the page is open.
- Demo stream and terminal layer (`css/terminal.css`, `js/ws/stream.js`, `live.js`, `view-live.js`, `graph.js`, `view-graph.js`): a Demo stream view that screens a seeded synthetic payment stream through the real engine and signs each decision into a rolling ledger (300 receipts, kept apart from the workspace ledger and evidence packs, off until started), live charts, a Counterparties view drawn as a funds flow (money in on the left, the address in the middle, money out on the right, link width = USD, top 8 per column with a "+N more" node that expands, a second column per side for two hops; exact list matches only, no scoring), alert bulk actions and keyboard triage. Removed in this version: the command palette, saved queue views, SLA timers, drafted case summaries, the status bar strip, Time and cost, and Chains and hours.
- Charts: Apache ECharts 5.6.0, vendored at `js/vendor/echarts.min.js` (version, source URL, SHA-256 and license in `js/vendor/README.md`), loaded by `app.html` as a plain deferred script. `js/ws/echart.js` holds the shared look (colours from the site's CSS tokens, so charts follow the theme toggle; thin lines, light gridlines, tabular numbers, one tooltip style with classes only, because the CSP forbids inline styles), `js/ws/chartx.js` the time-series and bar-list charts (HTML legend toggles, View as table, clean empty state, keyboard reading and zoom, Ctrl or Cmd plus wheel zoom, Reset zoom). The Counterparties funds flow is an ECharts sankey; Proof gap (interval plot, shares) and List archive (timeline) use ECharts too. KPI sparklines and the stream's decision-mix bar stay as small SVGs.
- Moat features (`js/ws/network.js`, `net-flow.js`, `gate.js`, `view-network.js`, `view-archive.js`, `view-proofgap.js`, `css/moat.css`): a Network view (demo members "Demo Exchange A, B, C" with real Ed25519 keys generated in the browser; inbound receipts verified offline, accepted or refused with reasons; pin and revoke are receipted; field names and rules follow `docs/PREREG_SHARED_RECEIPTS.md` on the research repo's `feat/network` branch), a payment gate (Network and Demo stream views), a List archive and a Proof gap view built from real result files (`data/archive.json` and `data/proofgap.json`, generated by `scripts/build_moat_data.py` from the research repos, each row naming its source file and its SHA-256), and a read-only Examiner role. Members, their payments and the demo list versions L1 and L2 are synthetic and labelled.
- `signin.html` (demo user picker, no credentials) and `waitlist.html` (early-access waitlist, mailto with its own subject).
- `contact.html` (Talk to us form) and `report.html` (problem report form): validated in the page; submit opens a prefilled email (mailto) and offers copy-to-clipboard if no mail app opens. Nothing is sent automatically. To use a hosted form service later, set `FORM_ENDPOINT` in `js/forms.js` and add its origin to `connect-src` in those pages' Content Security Policy.
- `faq.html`, `security.html`, `privacy.html`, `terms.html`.

`data/ofac_crypto_addresses.json` is generated by `scripts/build_ofac_bundle.py` from the Tollgate repo's OFAC snapshot; it records the source URL, publish date, download time and the SHA-256 of the raw SDN.XML. The sample payments are made up and the signing key is a published demo key.

Tests: `node --test tests/` (screening, signing, packaging, tamper detection, workspace logic, the funds-flow model, and the Live chain's log decoding, screening, signing, backoff and replay on mainnet logs recorded in `tests/fixtures/eth_mainnet.json`, no network). Playwright suites, each `python3 tests/<suite>.py <served-url>/ <screenshot-dir>`: `e2e.py` (every page, links, verifier pass/fail, the Get started flow, phone width, reduced motion, console errors, allowed origins), `e2e_workspace.py` (workspace flows), `e2e_moat.py` (Network, List archive, Proof gap, gate, examiner, charts, 1440 and 390 px, both themes), `e2e_pro.py` (demo stream soak at 20x, sign in, waitlist, bulk actions, both themes at desktop and phone, and that the removed features stay removed), `e2e_graph.py` (Counterparties at 2560, 1440 and 390 px: every node inside the canvas, no overlapping labels, +N more expands, keyboard and click selection; and Settings) and `e2e_chain.py` (Live chain on the recorded data, then with the RPC nodes blocked; `--live 60` adds a run against the real nodes). The browser suites answer the two RPC origins from the recording (`tests/rpc_fixture.py`), so they never depend on a third-party node, and they fail on a request to any other origin.
