API reference

Your systems send each transfer to Tollgate before it moves. Tollgate checks both addresses against the OFAC SDN list in force, returns the decision with a signed receipt, and keeps every receipt in one hash chain your analysts and examiners can check.

Where this runs: the API is part of the self-hosted kit, which runs on your own servers. The demo workspace (Try it, then Admin, Integrations) runs the same routes in your browser, on the bundled OFAC list and synthetic payments, so you can try them without an account.

Keys and scopes

An admin creates keys in the console. A key is tg_ followed by 43 characters and is shown once; Tollgate keeps only its SHA-256. Send it on every request:

Authorization: Bearer tg_...

Demo keys. Keys and webhook secrets you create in the demo workspace are demo credentials: they are kept in your browser, work only against the in-browser API, and must not be reused. In a real deployment the kit creates and keeps keys on your own server; never put a Tollgate key in browser code.

Each key carries scopes: screen for screening, read for receipts and usage, webhooks for webhook settings. The kit adds scopes for screening at a past time and for shared receipts. Give each system its own key with the fewest scopes it needs, so you can revoke one without touching the others. Creating and revoking a key are themselves signed receipts in the ledger.

Every error has the same shape. The code is stable; the message is for a person and can change.

Screen a transfer

POST /v1/screen
Authorization: Bearer tg_...
Idempotency-Key: withdrawal-1001
Content-Type: application/json

{
  "chain": "ETH",
  "to_address": "0x0123456789abcdef0123456789abcdef01234567",
  "from_address": "0x1111111111111111111111111111111111111111",
  "amount_usd": 1500,
  "originator_info_present": false,
  "reference": "withdrawal-1001"
}

Matching is exact, ignoring letter case. There is no name or fuzzy matching. outcome is ALLOW, HOLD (a policy rule, such as missing originator details at or above a threshold) or BLOCK (an address is on the list). A hold or a hit opens an alert for an analyst. The response names the list version and digest the decision used, and carries the signed receipt.

Send an Idempotency-Key on retries. The same key with the same body returns the stored decision with Idempotent-Replayed: true, signs nothing new and is counted once.

Usage

Tollgate meters per screened transaction: one count per signed decision, by key, with the outcome mix. Seats are not metered.

GET /v1/usage?from=2026-11-01&to=2026-11-30&group=day
GET /v1/usage?from=2026-11-01&to=2026-11-30&group=month&format=csv

A key sees its own usage. Dates are UTC and inclusive; a range is at most 1,100 days.

Verify a receipt

No key is needed, so a counterparty or an examiner can check what you send them. Send one receipt or a whole receipts file.

POST /v1/verify
{ "receipt": { ... } }

{ "verdict": "FAIL", "failed_check": "binding", "detail": "...", "signer": "03a1...", "signer_is_this_workspace": true }

The checks are the signature (Ed25519 over the canonical verdict), the binding of the verdict to the action, and the receipt's own hash. A receipts file is also checked link by link. The same checks run offline with the kit's verifier, so nobody has to trust this endpoint.

Webhooks

EventWhen
decision.createdEvery signed screening decision.
list.changedA new list version was applied, with how many addresses it added and removed.
address.newly_listedThe new list version contains an address you screened and allowed before. One event per address, naming the earlier payments, so you can review them.

Each delivery is signed with the endpoint's secret:

Tollgate-Signature: t=1763971200,v1=<hex HMAC-SHA256 of "1763971200." + raw body>

Check it before trusting the body, and refuse a timestamp more than 300 seconds from your clock. In Python:

import hashlib, hmac, time

def verify(secret: str, header: str, body: bytes, tolerance_s: int = 300) -> bool:
    parts = dict(p.split("=", 1) for p in header.split(",") if "=" in p)
    stamp, given = int(parts["t"]), parts["v1"]
    if abs(time.time() - stamp) > tolerance_s:
        return False
    want = hmac.new(secret.encode(), f"{stamp}.".encode() + body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(want, given)

Event ids repeat on a retry, so drop an id you have already handled.

Audit export

The Activity log exports every receipt as JSON or CSV. Each row carries prev_hash and this_hash, so a removed, edited or reordered row breaks the chain, and the JSON header names the head hash. Send the head hash to your examiner by a separate route so they can confirm nothing was cut from the end.

Limits of a decision

  • ALLOW means the exact address is not on the list version named in the receipt. It does not mean the address is safe.
  • Only the OFAC SDN digital currency addresses are checked. Names and other lists are out of scope.
  • Tollgate does not move or freeze funds. Your system acts on the decision.
